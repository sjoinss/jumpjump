# 점프점프 — UI 분석 및 구성안

> 「UI제작원칙」 2번(분석)과 26번(결과물)에 맞춰 정리한 문서입니다. 기준은 `dot-jump-climb-spec.md`이고, 구현하면서 이 문서도 같이 갱신합니다.

---

## 변경 사항 (2026-09-30, 사용자 결정 — 기획서보다 우선)

- **타이틀·첫 실행 선택 화면 없음**: 게임 장면 그대로 캐릭터가 바닥에 서 있고, 좌우에 카드 두 장 「시작하기(기본 캐릭터로)」「캐릭터 만들기」. 엔진 Phase에 `ready`를 추가해 처리
- **HUD**: 오른쪽 위에 ⚙ 설정 → ‖ 일시정지 순. 둘 다 아이콘만(스크린리더 이름 + 툴팁 `title` 제공). 설정은 시작 장면·게임 중 모두 열 수 있고, 게임 중에 열면 자동 일시정지 후 닫으면 일시정지 메뉴로 돌아옴
- **디자인 방향 변경**: 무난한 SaaS풍 → **귀여운 파스텔 게임풍**. 파스텔 채우기 + 잉크색 두꺼운 외곽선 + 아래 두께(눌리는 버튼), 둥근 게임 폰트(Jua, 빌드 때 번들), 도트 아이콘, 연한 도트 무늬 배경
- 일시정지 메뉴의 "타이틀로" → "처음으로"(시작 장면으로 돌아감)
- **테마 3종** (설정 → 테마, 즉시 적용·자동 저장): 도트 놀이터(기본) / 솜사탕(연한 분홍 외곽선, 더 둥글게) / 꿈나라(라벤더·하늘빛, 달과 별). UI 색은 `tokens.css`의 `[data-theme]`, 게임 장면 색은 `src/game/themes.ts`. 외곽선 색(`--color-line`)과 글자색(`--color-ink`)을 분리해서 어느 테마든 글자 대비 AA 유지. `settings.theme`은 v1에 추가된 항목이라 없으면 기본 테마로 읽음(마이그레이션 없음)
- **에디터 키보드 그리기 없음**: 도트는 터치·마우스로만 그린다(방향키 커서·스페이스 칠하기 제외). 메뉴·버튼·탭·대화창의 키보드 조작과 Ctrl+Z 같은 단축키는 유지
- **조작법 안내(4단계)**: 첫 판에서 "시작하기"를 누를 때 한 번만 대화창으로 표시. 터치 기기는 드래그, 마우스·키보드 기기는 ←→/A·D + 마우스 안내(둘 다 있으면 둘 다). ✕로 닫아도 본 것으로 기록. 기본 캐릭터 고르기는 별도 화면 없이 에디터의 "불러오기"에서
- **이미지 불러오기(5단계)**: 에디터 캐릭터 탭의 「불러오기·크기 → 내 이미지 불러오기」, 이미지 프레임의 「이미지 바꾸기」, PC는 캐릭터 탭에 파일 끌어다 놓기. 조정 화면은 에디터 위에 덮는 전체 화면(대화창보다 공간이 필요해서)
- **데이터 관리(6단계)**: 설정 → 데이터 관리. 내보내기 기본은 그림만(캐릭터·발판·동료·팔레트), "전체 백업"은 설정·최고 기록까지. 불러오기 때 온보딩 기록은 이 기기 것을 유지. 주기적 백업 안내는 직접 그린 그림이 있고 마지막 내보내기(또는 안내)에서 14일이 지나면 시작 화면에 표시
- **점수 = 높이(m)** (2026-10-01): "처음 밟은 발판마다 +1" 대신, 이번 판에서 대열 맨 아래 줄 발밑이 올라간 가장 높은 곳을 m로 표시(내림, 떨어져도 줄지 않음). 1m = 캐릭터 키 72px(`CONFIG.score.pxPerMeter`). HUD·게임오버·최고 기록은 "123m", 스크린리더는 10m마다. 기존 체감 속도에 맞춰 높이 기준도 m로 옮김: 지역 지상 75m / 하늘 260m / 우주 600m(섞임 ±25m), 동료 후보 25·75·175·350·650m 이후 300m 간격, 고점프 15m·일회용 35m부터. 이전에 저장된 최고 기록(발판 수)은 그대로 두고 새 기록으로 덮어씀
- **동료 그리기(10단계)**: 주인공·발판 에디터(`EditorScreen`)를 그대로 쓰고 `companion` 모드면 탭 없이 동료 한 명 + 이름(선택, 12자) + 「주인공 가이드」 토글, 착지 프레임엔 「내 기본 그림 깔기」(주인공 편집의 「기본 그림 깔기」와 라벨 구분). "불러오기·크기"에서 동료는 기본 캐릭터 대신 「주인공 그림 가져오기」. 게임 중: 선택창 "예, 그릴래요"(빈 슬롯) / "예"·"수정하기"(그림 있음) → 게임 멈춘 채 그리기 → 완료하면 슬롯 저장 후 합류(11단계에서 미니게임이 끼어듦). "그만 그리기"는 초안(슬롯별 `editor.draft.companion.N`)을 남기고 후보 유지, 거절로 세지 않음. 설정 → 동료: 최대 인원(0~5, 다음 판부터, 자동 설정 표시), 슬롯 1~5 그리기/수정·삭제, 전부 삭제(확인창, 기본 포커스 취소)
- **미니게임(11단계)**: 그림 완성 / 그림 있는 슬롯의 "예" → 미니게임(랜덤 1종, 바로 앞 게임은 피함, 재도전 없음) → 성공이면 합류, 실패면 그 후보만 없어지고 게임 계속(그림은 슬롯에 남음, 거절로 세지 않음). 화면: 위쪽 HUD(이름 · 진행 텍스트 · 하트 목숨, 잃은 하트는 점선 빈 하트 · 일시정지) + 판(360×560, 비율 유지) + 3초 카운트다운 카드(목표 + 터치/PC 조작법 아이콘·글) + 결과 대화창("계속하기"). 창 벗어남·Esc·P면 멈추고 다시 시작할 때 3초 카운트다운. 4종 모두 목숨 3개(기획서엔 슈팅·피하기만 명시 — 첫 시도 성공률 목표에 맞춰 줄넘기·파닥파닥에도 둠). 줄넘기는 주인공이 넘고 동료가 줄을 돌림, 나머지는 동료가 주인공
- **설정·연출·소리(12단계)**: 설정 섹션 순서 동료 | 캐릭터·발판 | 연출 | 테마 | 데이터 관리 | 앱. 캐릭터·발판의 에디터는 설정 위에 덮어서 열어(게임 중에 열어도 판이 끊기지 않음) 발판은 기본 발판 탭으로 바로 연다. 연출 스위치 4개(화면 흔들림 / 파티클·착지 이펙트 / 효과음 / 특수 발판 표식) + OS 동작 줄이기 안내. 앱: 최고 기록 초기화(위험, 기본 포커스 취소) — 설치는 14단계. 흔들림은 배경을 빼고 바닥·발판·캐릭터만 2~3px(고점프·일회용·합류), 파티클은 착지 먼지·고점프 반짝이·일회용 조각(그 발판 그림의 주된 색)·합류 별, 잉크 테두리. 느린 프레임이 30% 넘으면 파티클 절반. 효과음은 Web Audio 8비트(착지·고점프·부서짐·후보·성공·실패·게임오버·지역·카운트다운), 첫 입력에서 켜고 백그라운드에서 멈춤, 일시정지 메뉴에 효과음 스위치. 일시정지 "계속하기"(또는 Esc) → 화면 가운데 큰 숫자 3·2·1(live region으로도 읽음) 후 재개, 세는 중 창을 벗어나면 다시 일시정지 메뉴
- **결과 이미지(13단계)**: 게임오버 창 순서 = 점수 → 다시 하기 → 결과 카드(왼쪽 148px 움직이는 미리보기, 오른쪽 이미지 저장 · GIF 저장 · 공유) → 캐릭터 만들기 · 처음으로. 카드는 `src/share/`의 한 렌더러로 미리보기·PNG(1080, 대표 프레임)·GIF(720, 32프레임×50ms) 모두 그림. 배경은 게임 배경 렌더러를 게임오버 높이로 재사용, 위 반투명 판에 지역 이름 + "123m" + NEW·동료 배지, 각자 기본 발판 위에서 squash & stretch로 폴짝(착지 단계에 착지 프레임), 도트 스티커, "점프점프" 워터마크. 4~6명은 앞줄 3 + 뒷줄(60px 위, 엇갈림). GIF는 직접 만든 인코더(미디언 컷 + 디더링(이미지 캐릭터 있을 때만) + LZW)를 Web Worker에서, 진행률 막대(숫자 %) + 취소 + 실패 시 원인과 "GIF 다시 시도". 휴대폰은 공유 창 먼저, PC는 다운로드, 둘 다 안 되면 "이미지를 길게 눌러 저장하세요" 창. 공유 버튼은 파일 공유를 지원하는 브라우저에서만. 동작 줄이기면 미리보기는 대표 프레임에서 정지(저장은 정상)
- **PWA(14단계)**: 서비스 워커는 직접 작성(`scripts/sw.template.js`) — `npm run build` 뒤 `postbuild`가 `out/` 파일 목록과 내용 해시로 `out/sw.js`를 만든다(파일이 바뀌면 버전이 바뀜). 페이지 이동은 캐시한 앱 셸, 나머지는 캐시 먼저. 새 버전은 자동 교체하지 않고 시작 장면 맨 위 "새 버전이 있어요 · 업데이트"(설정 → 앱에도) → 누르면 교체 후 새로고침. 개발 서버에서는 등록하지 않음. 설치: Android 등은 「앱으로 설치」(브라우저 설치 창), iOS는 단계 안내 창 + "설치 전에 데이터를 내보내세요" + 전체 백업 내보내기. 버튼 위치: PC는 프레임 옆 최고 기록 아래, 휴대폰은 시작 장면 로고 아래, 설정 → 앱. 설치된 상태면 숨김. 저장소 보존 요청은 그림을 처음 저장할 때·설치했을 때(일부 브라우저가 묻는 창을 띄워서 첫 화면에선 안 함). 모바일 브라우저 탭은 첫 터치에 전체화면 시도
- **검수(15단계)**: 결과는 `docs/qa-checklist.md`. 터치 영역 44px(탭·단계 선택·내보내기 프리셋은 실제 높이, 에디터 칩·팔레트 색은 누르는 영역만 넓힘), 성공 초록 #2b764a(대비 4.8:1), 세 테마 대비를 테스트로 고정
- **UI 다듬기 (2026-10-01)**: 기록 구분 이름을 "동료 있음/없음" → **"동료 모드 / 혼자 모드"**(판 시작 때 동료 최대 인원 기준), 게임오버·결과 이미지 배지는 이번 판에 실제로 함께한 동료("동료 2명과 함께"/"동료 없이"). 스크롤바는 라벤더 알약 + 잉크 외곽선(가로는 얇게, 화살표 없음). 한글은 띄어쓰기 단위 줄바꿈(keep-all). 설정 섹션을 카드로, 최고 기록은 두 칸, 위험 동작은 섹션 맨 아래. 결과 카드는 미리보기 가운데 + 버튼 두 칸. 미니게임 판은 아래에 붙임. 화면 전환용 제목 포커스는 링 없음. 하늘·우주 높이는 지금 값 유지(사용자 결정)
- **캐릭터 모습 셋 (2026-10-01, 기획서 4-4 변경)**: 기본(올라갈 때·서 있을 때, 필수) / 내려갈 때(선택) / 착지(선택) 중 어디까지 그릴지 고른다. 안 그린 모습은 기본 그림. 게임은 떨어지는 동안 내려갈 때, 발판에 닿는 순간 0.2초 착지. 결과 GIF도 하강 단계에 내려갈 때. 저장 형식 v2 `{ base, fall?, land? }` — v1 데이터·예전 내보내기 파일·에디터 임시 저장본은 자동 변환(예전 2장 = 기본 + 착지). 에디터 프레임 줄: "기본 · + 내려갈 때 · + 착지" + 고른 모습이 언제 보이는지 한 줄 + 삭제, 캐릭터 탭의 "불러오기·크기" 칩은 "불러오기"로 줄임
- **도트 크기 이미지 → 도트 (2026-10-01, 기획서 21 "이미지의 도트화 변환 제외"를 좁게 변경)**: 이미지가 도트 격자와 **정확히 같은 크기(16×18 또는 32×36px)**일 때만 "도트로 바꿔서 고치기 / 이미지 그대로 쓰기"를 고른다(픽셀 하나 = 칸 하나, 반투명은 128 기준, 네 모서리가 같은 색이면 테두리와 이어진 그 색을 지우는 선택지). 다른 크기는 줄이거나 늘리지 않고 이미지로만. 등록한 이미지 그림은 고치지 않는다(도트로 그린 것만 수정)
- **수정 묶음 (2026-10-01)**: 결과 PNG는 모두 발판에 서 있는 모습, 위쪽 글씨·배지 가운데 정렬, 아주 큰 점수는 쉼표 + 글씨 줄임(이미지·HUD·게임오버·기록), 맨 아래 글씨는 저장 전 입력란에서 바꿈(설정에 기억, 비우면 안 씀). 이미지·GIF 저장은 기기에 바로 다운로드, 공유는 공유 버튼만. 동료 1명당 발판 6px 좁게(좁아진 발판 그림은 같은 비율로 작게). 지역마다 게임 속도 1.0/1.05/1.1/1.15배. 게임 중 squash & stretch 점프(파티클·착지 이펙트 스위치). 기본 캐릭터 4종 모두 세 모습, 동료도 기본 캐릭터에서 고름. 일회용 발판을 밟으면 그 높이가 새 바닥선(화면 아래 끝이 올라옴). 동료 거절 시 구슬은 사라지고, 3번 거절하면 설정과 상관없이 지금 동료 수로 자동 설정(설정에서 바꾸면 거절 횟수 0부터)
- **미니게임 다듬기 (2026-10-01)**: 미니게임 판을 **테두리 두른 창**(게임풍 외곽선 + 입체 그림자)으로 가운데에 띄움 → 창 위·아래 끝이 천장·바닥이라 파닥파닥 위 기둥이 천장에 붙어 보임(예전엔 판을 아래에 붙이고 남는 위쪽을 같은 하늘색으로 채워서 기둥 위가 빈 것처럼 보였음). 창 밖을 눌러도 조작됨. 줄넘기 판은 360×320으로 낮춤. 난이도: 줄넘기 7번·넘을 때마다 줄이 빨라짐(1.5→1.2초), 슈팅 적 3×6=18마리·적 탄 더 자주·빠르게, 파닥파닥 기둥 6개·속도 1.6배(느린 반응 자동 플레이 성공률 약 95%→70%), 피하기 더 자주·빠르게 떨어짐(약 79%)
- **일회용 발판 무너짐 (2026-10-01, 수정 묶음의 "새 바닥선"을 바꿈)**: 밟으면 화면 아래 끝을 확 끌어올리던 방식이 순간이동 같아서, 화면은 그대로 두고 **그 아래 발판이 밟은 곳에서 가까운 것부터 차례로(900px/초) 덜덜 떨다 떨어지며 사라짐**. 무너지기 시작한 발판은 바로 밟을 수 없어서 놓치면 화면 아래로 떨어져 끝(규칙은 같음). 동작 줄이기면 떨림 대신 흐리게. 피하기 미니게임의 낙하물은 노란 별 공 → **폭탄**(심지 불꽃 깜빡임), 목표 문구 "폭탄을 피해 15초 버텨요"
- **최고 기록 선·색 고르기·시작 카드 (2026-10-01, 캐릭터 공유 링크는 만들었다가 사용자 결정으로 뺌)**: 게임 중 이번 모드(동료/혼자) 최고 높이에 점선 + 오른쪽 "최고 87m" 깃발(넘으면 금색). 에디터의 지금 색을 누르면 기기 기본 피커 대신 **채도·밝기 네모 + 색조 막대 + 색 코드** 창(끄는 대로 바로 적용, 취소하면 원래 색). 시작 카드 두 장은 바닥 위 → 화면 세로 가운데(양 끝 그대로)
- **테마 2종 추가 (2026-10-01)**: 「바닷속」(푸른 UI, 거품처럼 둥근 모서리)과 「블록 월드」(잔디·흙·돌 색, 네모난 모서리, 마인크래프트풍이지만 이름·무늬는 직접 만듦). 지역 이름·경계·배경은 이제 테마마다 따로(`SCENE[테마].regions`) — 바닷속은 해저 → 수면 → 하늘 → 우주(높이는 기본과 같음), 블록 월드는 네더(0) → 동굴(150m) → 지상(500m) → 하늘(1200m) → 우주(2500m). 게임 속도(난이도)는 테마와 상관없이 기본 지역 높이를 따른다. 바닷속: 75m에 실제 수면이 있어 올라가면 물 밖으로 나옴(물속: 해초·거품·물고기·빛줄기, 물 위: 구름·갈매기, 시작 바닥은 모래). 블록 월드: 세상의 단면 — 높이마다 블록 재질이 정해져 경계가 실제로 지나감(네더랙·용암·발광석 → 돌·광석 → 흙·잔디·나무), 양옆은 밝은 블록 벽·가운데는 어두운 뒷벽, 블록은 32줄씩 이미지로 미리 그려 둠(프레임당 5.6ms → 0.3ms). PC 배경 가운데 두 줄도 테마 색 토큰으로
- **지역 높이 늦춤·스킨 불러오기 (2026-10-01)**: 사람들이 수천 m까지 가서 배경이 너무 빨리 바뀜 → 기본 지역 75/260/600m → **300/1000/2500m**(섞임 ±25 → ±60m), 블록 월드 150/500/1200/2500m. 게임 속도가 오르는 높이는 지역과 떼어 예전 그대로(75/260/600m, `CONFIG.regions.speedSteps`) — 난이도는 같고 배경만 늦게 바뀜. 에디터 이미지 불러오기에서 블록 게임 스킨(64×64·64×32 PNG)을 고르면 머리·몸·팔·다리 앞면을 떼어 **32×36 꼬마 도트 캐릭터**(머리 2배, 다리 8줄)로 조립해 "도트 캐릭터로 바꾸기 / 이미지 그대로" 선택(덧입는 층 반영, 예전 스킨은 왼쪽을 뒤집어, 얇은 팔 자동 판별)
- **마인크래프트 아이디로 스킨 (2026-10-01)**: 이미지 불러오기 첫 화면에 「마인크래프트 아이디로 불러오기」(영문·숫자·밑줄 3~16자). 공식 API는 브라우저 요청(CORS)을 막아서 minotar.net(없는 아이디는 404 → "찾을 수 없어요")에서 받고, 닿지 못할 때만 mc-heads.net. 아이디만 보내고 받은 PNG는 파일 불러오기와 같은 검사 → 스킨 → 도트 캐릭터 단계로. 예전 64×32 스킨의 꽉 찬(검은) 모자 층은 게임처럼 없는 것으로 봄
- **움직이는 발판 (2026-10-01, 기획서 3-4 "후순위 확장 후보"를 추가)**: 새 발판 종류. 좌우 벽 사이를 45~85px/초로 오가고(지역 속도 배율 적용) 60m부터 12% → 175m 20% → 350m 28%. 하늘색 기본 그림, 에디터 "움직이는" 탭, 색약 표식은 좌우 화살표. 예전 데이터·파일에 그림이 없으면 기본 그림으로 채움

## E. 반응형 전략 (원칙 26-4)

- **기준 해상도**: 게임은 논리 폭 360 고정, 높이 640~840. `scale = min(화면폭/360, 화면높이/640)`로 맞추고, 남는 영역은 배경으로 채움(레터박스 없음)
- **≤480px (360·390 모바일)**: 게임 전체화면. 메뉴 화면은 한 열, 버튼은 폭 100%, 설정은 전체화면
- **>480px (768 태블릿 ~ 1440 데스크톱)**: 가운데 세로 프레임. 배율은 1, 1.5, 2… 0.5 단위로 스냅하고 남는 높이는 논리 높이(최대 840)로 흡수. 프레임 좌우에 240px 이상 여유가 있으면 최고 기록·설치 버튼 표시, 없으면 숨기고 타이틀 화면에서 보여줌
- **메뉴 화면(설정·에디터)**: 프레임 안에서 스크롤. 가로 스크롤 없음, 긴 텍스트는 줄바꿈
- **가로 모드(모바일)**: "세로로 돌려주세요" 안내 표시

## G. 접근성 전략 (원칙 26-5)

- 화면마다 `<main>` + `<h1>` 하나, 섹션은 `<section>` + `<h2>`
- 포커스 링은 절대 지우지 않음(`:focus-visible` 3px 링). 화면이 바뀌면 새 화면의 `<h1>`로 포커스 이동
- 캔버스: `role="img"`가 아니라 `aria-label`을 단 조작 영역 + 텍스트 HUD. 점수·배너·카운트다운·결과는 공용 live region으로 전달
- 모든 조작을 키보드로 가능하게: 인게임(←→/A·D, Enter/Space, Esc/P), 에디터(방향키 + 스페이스), 다이얼로그(Tab 순환, ESC)
- 색에 기대지 않기: 스위치는 텍스트, 특수 발판은 도형 표식, 후보는 테두리·흔들림, 토스트는 기호 + 문장
- 대비: 본문 AA(4.5:1) 이상, 큰 글씨·UI 경계 3:1 이상. HUD 텍스트는 외곽선/반투명 판 위에 표시
- `prefers-reduced-motion`: 배너 슬라이드·흔들림·파티클·PC 배경 장식 애니메이션 끔

## H. 디자인 방향 (원칙 26-7) — 귀여운 파스텔 게임풍

- **형태 언어**: 파스텔 채우기 + 잉크색(`--color-ink`) 3px 외곽선 + 아래 4~6px 두께. 누르면 두께만큼 내려감. 모서리 14~28px
- **색**: 딸기우유(primary) · 라벤더(secondary) · 민트 · 버터 · 하늘 · 크림. 파스텔은 채우기에만 쓰고 글자는 잉크색 → 모든 조합 6:1 이상. 상태색(success/warning/error)은 기호와 함께
- **글자**: 제목·버튼·HUD·숫자는 번들 폰트 Jua(1종), 긴 설명은 시스템 한글 폰트. 크기 34/26/21/18/16/14, 14px 미만 없음
- **장식**: 연한 도트 무늬 배경, 도트 아이콘(`PixelIcon`), 캔버스는 계단식 파스텔 띠 + 도트 구름·반짝이 + 풀밭 바닥. 로고만 살짝 둥실
- **모션**: 버튼 누름 120ms, 다이얼로그·토스트·카드 등장은 살짝 튀는 ease(`--ease-pop`). `prefers-reduced-motion`이면 로고 둥실·구름 흐름·캐릭터 제자리 점프 끔
